# Dashboard Documentation — Supra AI Electronics Compliance Audit Dashboard

## Purpose

This dashboard is the communication layer for Chleo (Head of Procurement and Supply Chain Operations): it answers, at a glance, *"which supplier certificates have a problem, how serious is it, and which supplier should I follow up with first?"* — without requiring anyone to read the underlying compliance rules or LLM extraction logic. It is built directly from real output of the audit pipeline (`langsmith/trace_sample.py`), not illustrative or invented data.

## Data source

`data/tableau_export.csv`, regenerated by `trace_sample.py` on every real pipeline run with 7 rows, one per certificate in the current evaluation set.

## Layout and metrics (5 metrics across 3 views, within the Round 1 5–7 metric guideline)

### KPI Scorecard (top row)

| Metric | Value | Why it's here |
|---|---|---|
| Count of Certificate ID | 7 | Scope/volume — how many audits this reflects |
| Flagged Count | 5 | Combined FLAGGED + REJECTED count (2 + 3) — "needs attention" total |
| Pass Rate (%) | 29% | Headline health metric — the single number a CEO/procurement head would ask for first |


### Audit Status Breakdown (bar chart)

Counts by status: FLAGGED (2, yellow), PASS (2, green), REJECTED (3, red).

### Supplier Risk Matrix (horizontal bar chart)

Average screening priority score per supplier, sorted descending, color-coded by severity band:

| Supplier | Score | Status |
|---|---|---|
| PowerMax Energy Ltd. | 95.00 | REJECTED |
| Shenzhen Shentech Electronics | 90.00 | REJECTED |
| Apex Display Systems Inc. | 85.00 | REJECTED |
| Guangzhou Wearable Tech Co. | 75.00 | FLAGGED |
| Dongguan Peripheral Cables Co. | 60.00 | FLAGGED |
| SoundHome Audio GmbH | 10.00 | PASS |
| AudioTech Solutions HK Ltd. | 10.00 | PASS |

This view directly supports supplier-level decisions (which supplier relationship needs escalation), not just document-level ones — useful since procurement conversations happen at the supplier level, not the certificate level.

### Review Queue (detail table)

Every certificate, grouped by status, with the specific flagged issue text visible inline (e.g., *"CRITICAL: Unrecognized or suspicious laboratory accreditation ID (FAKE-ACC-000)"*). This is the evidence layer — it's what lets a reviewer act on a finding without opening the original PDF, and it's the direct link back to the audit trail described in `langsmith_documentation.md`.

## Design choices and why

- **Color consistency across all three views** (red = REJECTED, yellow = FLAGGED, green = PASS) — a stakeholder learns the color code once and reuses it across the whole dashboard.
- Every REJECTED/FLAGGED row shows *why*, matching the project's core design principle from `opportunities_risks.md` — every finding should answer "what's wrong, what's the evidence, what should the reviewer do next."
- **No automated decision framing**: the dashboard presents findings for human review; it does not present itself as a final compliance determination, consistent with the project's explicit scope boundary (AI screens and prioritizes, humans decide).

## Known limitations

- **Small sample (7 certificates)** — this dashboard demonstrates the mechanism and communication layer at pilot scale, not portfolio-wide coverage. At the target client's real scale (~2,000 SKUs), this same structure would need to support filtering/drill-down by category and time period, which isn't built yet.
- **Static snapshot**: this is a point-in-time CSV export, not a live-refreshing connection to the n8n pipeline. A production version would need the dashboard to read from the same Notion databases the n8n workflow writes to, not a manually regenerated CSV.
- **Supplier Risk Matrix shows averages only** — with more certificates per supplier in a real deployment, an average could mask a supplier with one very bad certificate and several good ones; a real version should show count alongside average, or a distribution rather than a single bar.
