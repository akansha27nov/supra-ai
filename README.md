# Supra AI — AI-Assisted Supplier Compliance Screening

**Capstone project — Round 1**

## Scenario

**Client:** Chleo, Head of Procurement and Supply Chain Operations at a mid-sized European omnichannel retailer (~200 employees, ~2,000 active SKUs, consumer electronics sourced from EU and non-EU suppliers).

**Problem:** Supplier compliance documentation (CE/RoHS certificates, test reports, declarations of conformity) is spread across PDFs, spreadsheets, and email, and checked manually. Chleo needs a faster way to identify incomplete, expired, or inconsistent supplier documentation and prioritise which products need human review — without an AI system making the compliance decision itself.

**Solution shape:** an AI-assisted screening layer that extracts structured data from supplier certificates, checks it against deterministic compliance rules and the internal SKU catalog, and surfaces prioritised, evidence-linked findings on a dashboard for human reviewers. The AI extracts; a transparent, auditable rule engine decides; a human approves.

## Setup

1. Clone/unzip the repository.
2. Create a Python environment and install dependencies:
   ```bash
   pip install -r requirements.txt
   ```
3. Copy `.env.example` to `.env` and fill in real credentials (OpenAI API key, LangSmith API key, and Notion/Telegram credentials if running the full n8n workflow).

## Running the pipeline

```bash
python langsmith/master_benchmark.py
```

This runs the real extraction + rule-based screening pipeline against all 7 synthetic certificates and all 5 real-world certificates, prints an expected-vs-actual comparison against `data/ground_truth.json` and `data/real_ground_truth.json`, and regenerates `data/tableau_export.csv`, `data/tableau_export_real.csv`, and `data/tableau_export_combined.csv` from the real output. Every run is traced in LangSmith (project name set via `LANGCHAIN_PROJECT` in `.env`) — see `langsmith_documentation.md` for what's traced and why.

**Current validated result: 12/12 (100%) agreement with labeled ground truth** — 7/7 on the synthetic set and 5/5 on the real-world set — using real PDF text and a live LLM extraction call. See `round1_decision.md` for the honest caveat on what this figure does and doesn't prove (small real-world sample, self-declarations only so far).

To run only the original single-dataset pipeline:
```bash
python langsmith/trace_sample.py
```

## What Round 1 does and does not prove

Round 1 demonstrates that the end-to-end concept is feasible, that deterministic policy screening can be separated from AI extraction, and that real-world documents reveal useful failure modes that synthetic data alone would not expose (see `round1_decision.md`). It does **not** demonstrate production-scale reliability, full generalisation across EU electrical-product documentation, or a measured client ROI — those are explicit Round 2 goals, scoped in `rollout_plan.md`.
